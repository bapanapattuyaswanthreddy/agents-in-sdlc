GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、自分のマシン上でリアルタイムに進む作業について、ツール呼び出しやファイル編集を確認できます。各差分をチャット内でレビューし、個別の変更を採用または元に戻し、会話から離れずに追加のプロンプトで作業を調整、拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、ハイコントラスト モードと合わせてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイコントラスト モードを実装しています。作業の途中でデザイン チームから追加の依頼がありました。既定のテーマを暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加します。新しい会話を最初から開始する代わりに、既存のセッションに指示を出して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各ステップが表示されます。調査したファイル、実行したコマンド、提案した編集などを確認できます。ファイル編集は差分と **Keep** / **Undo** 操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求められるターミナル コマンドなどが表示されます。
3. ファイル編集が提案されると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイルの一覧を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールから許可を求められると、エージェントは一時停止して **Allow** を表示します。自分が許可できるコマンドだけを承認してください。

5. エージェントがハイコントラスト モードの実装を完了するまで待ちます。変更の概要を含む最終メッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイコントラスト モードが追加されたら、同じ会話にライト モードの切り替えも追加します。同じチャット セッションを続けると、エージェントは前の作業で変更したコンポーネント、スタイルの方針、local storage のパターンなどのコンテキストを維持できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調査し、ライト モードの追加を提案します。
3. ハイコントラスト モードと同じように、新しい編集を確認して各差分の **Keep** または **Undo** を選択します。
4. エージェントの方向性が意図と異なる場合 (たとえば切り替え UI を望まない方法でリファクタリングしようとする場合) は、チャット入力欄の横の **Stop** ボタンで停止し、追加のメッセージで説明します。

> [!TIP]
> 作業中のセッションに指示すると、最初からやり直すよりも速く調整できます。追加プロンプトで修正を依頼します (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方向を修正します (「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを追加する」)、範囲を広げます (「両方の切り替えにキーボード ショートカットも追加する」)。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更ファイルの一覧をレビューします。Astro コンポーネント、スタイル、関連テストなどが含まれるはずです。
3. 変更ファイルをいくつか開いて差分を確認します。カスタム エージェントのアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確かめます。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、進行中のセッションを監視して方向づけました。ファイル編集を確認して採用または拒否し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または元に戻しました。
- セッションの途中で追加プロンプトを使って作業を調整しました。
