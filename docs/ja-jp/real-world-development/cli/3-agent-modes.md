最初に、プロジェクトに小さな機能を追加しました。より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot CLI は既存の組織のワークフローに沿って動作するため、適切な方法で適切なものを構築できます。このレッスンから複数のレッスンにわたり、Issue を起点に機能を作成し、コードの妥当性と動作を確認して、最終的にプロジェクトへマージする、一般的なエージェント主導の開発プロセスを進めます。

> [!NOTE]
> 機能開発の間は、同じ会話とブランチを使います。通常は作業するファイル タイプごとに別のブランチや PR を使いますが、ここでは中心的な概念に集中するため手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub Issue から Copilot の新しい会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- ポート フォワードしたブラウザーで機能を手動検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加し、QA エージェントを作成して、機能 PR を作成します。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がカテゴリやパブリッシャーでゲームを絞り込める必要があります。バックログの Issue には機能が記述されていますが、カテゴリを組み合わせる方法など、実装前に合意すべき詳細があります。Plan モードで決定事項を整理してから、範囲を定めた実装を Autopilot に任せます。

## 背景

AI コーディング エージェントを開発ワークフローに取り入れても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は次のような手順で作業します。

1. 実施内容を記載した Issue から始めます。
2. 構築するものの計画を作成します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プル リクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細な進め方はチームや組織によって異なりますが、多くは上記の手順を基本としています。

この標準的な方法に従うことで、AI が生成したコードも要件を満たし、手作業で書いたコードと同じ検証プロセスを経るようにできます。

## 会話モード

**会話モード**では、エージェントにどの程度の自律性を与えるかを設定します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive:** エージェントと一緒に作業します。エージェントは変更を提案し、続行前に入力を待ちます。
- **Plan:** エージェントが先に計画を作成します。プロジェクト ファイルの編集はできません。
- **Autopilot:** エージェントが自律的にコードを書き、テストを実行し、タスクが完了するまで反復します。

まず Plan モードで計画を確認し、次に Autopilot で実装します。

## Issue から始める

フィルター機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルター作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** という Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が追加されます。`#` を使うと、GitHub 上の Issue やプル リクエスト (PR) をコンテキストに含められます。

## フィルター機能を計画する

計画を立てると、Copilot に作業を依頼する前に、機能の実装方法やタスクの進め方を決められます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替えて、計画を作成するよう Copilot に依頼します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下に **Plan** と表示されていることを確認します。
2. 前の手順で追加した Issue の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査し、適切なアプローチを検討して計画を作成します。

3. フィルターの動作について質問された場合は、自分の希望に沿って回答します。どの回答が正しいということはありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を確認します。
6. 決定した内容と異なる部分があれば、修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot では、Copilot が完了したと判断するまで問題に取り組み、反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンで同等の名前の項目を選択します。
2. プロンプトの下に **Autopilot** と表示されていることを確認します。
3. Copilot が計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画を確認してください。依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決します。

## 実装をレビューして検証する

生成されたコードも、ほかのコードと同じようにマージ前にレビューします。コードを確認し、サイトを実行して問題がないか確かめます。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果が Issue と計画時の決定事項に沿っているか比較します。
4. レビューが終わったら <kbd>Esc</kbd> を押して差分表示を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を試す

コードに問題がなさそうでも、正しく動くかを確認しましょう。前と同じようにアプリを起動し、Codespaces のポート フォワードを通じてサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. 計画で合意したカテゴリ、パブリッシャー、組み合わせによるフィルターを試します。
4. リセットや結果が空の場合の動作が Issue と決定事項に沿っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーの停止を依頼します。

## まとめと次のステップ

異なる会話モードを使って機能を構築し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub Issue から Copilot の新しい会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- ポート フォワードしたブラウザーで機能を手動検証しました。
